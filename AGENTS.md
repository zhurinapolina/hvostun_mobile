# Как переносить интерфейс Хвостуна в рабочий код

Этот файл — инструкция для разработчика и для ИИ-ассистента (Claude Code, Cursor, Copilot и т. п.). Цель — перенести мобильный интерфейс **один в один**: та же разметка, те же стили, те же тексты, то же поведение. Сервер и хранение данных делаются заново по `docs/handoff.md`.

## Источники правды (по порядку)

1. **`handoff/screens/*.html`** — эталон каждого экрана и состояния. Как выглядит эталон в браузере на 390 × 844, так должен выглядеть экран в продукте. Карта эталонов — `handoff/README.md`.
2. **`prototype/src/app.js`** — эталон поведения: переходы между экранами, состояния главной и меню, проверки полей, анкета, чат. Это рабочий код на чистом JS, его логику можно переносить напрямую.
3. **`docs/handoff.md`** — данные, статусы, тексты ошибок, модель данных и запросы к серверу.
4. **`design-system/hvostun-design-system.md`** — токены и компоненты (CSS — раздел 12).
5. **`prototype/src/cbarq-questions.json`** — все тексты анкеты.

Если источники расходятся — прав эталон экрана, затем `app.js`, затем остальное.

## Обязательные правила

1. **Копировать, а не перерисовывать.** Разметку, классы и CSS экрана берите из эталона как есть. Меняйте только способ подставить данные (кличка, ответы, сообщения чата). Не «улучшайте» отступы, цвета, шрифты и размеры.
2. **Стили каждого экрана изолировать.** CSS из блока «стили этого экрана» подключать только к своему экрану (CSS Modules, scoped-стили, Shadow DOM или префикс экрана). **Нельзя сливать стили разных экранов в один глобальный файл**: одинаковые селекторы на разных экранах означают разное, и правила перебивают друг друга.
3. **Общий адаптив — один раз.** Блок «общие правила адаптива» (= `prototype/src/app.css`) подключить глобально. Правила `#panel`, `#frame`, `#kbd` и `@media (min-width:760px)…` для пульта — оболочка прототипа, в продукт не переносить. Контейнерные запросы считаются от `#app` (`container: app / size`) — сохраните корневой `#app` или замените на свой корень с тем же `container`.
4. **Тексты не менять.** Ни слова, ни регистра, ни кавычек «», ни тире —. Варианты ответов анкеты — как в эталоне.
5. **Цвета — только из дизайн-системы.** Новых не добавлять.
6. **Иконки и иллюстрации — встроенные SVG из эталонов** (`fill="currentColor"` у иконок). Иллюстрации DiCreate лицензионные, их не перерисовывать и не заменять.
7. **Поля ввода — не меньше 16 px**, иначе iPhone увеличивает страницу при вводе. Числовые поля (люди, вес, рост) принимают только цифры, вес — с одной цифрой после запятой.
8. **Анкета строится из шаблонов и данных.** Вступление раздела, вопрос и свободный ответ — один шаблон каждый (эталоны `s7-section-*-intro`, `s7-question*`, `s7-free-answer*`) плюс тексты из `cbarq-questions.json`. Маршруты и правила «Назад»/«Далее» — функции `prevOf`, `nextOf`, `anketa`, `vvForm` в `app.js`. Ответ сохранять сразу, позицию — для «Продолжить» на главной.
9. **Состояния — как в эталонах.** Неактивная «Далее» (`.b0`), выбранный вариант (сиреневый, без тени), ошибки у полей (справа в строке названия), загрузка (`aria-busy`), закрытые карточки — ровно как в соответствующих эталонах.

## Адаптив

Интерфейс один для всех телефонов: от 280 до 430 px по ширине в портрете и горизонтальное положение до 932 × 430. Ничего не верстать отдельно под устройства — всё уже описано правилами.

1. **Правила в `prototype/src/app.css`** работают через контейнерные запросы от `#app` (`container: app / size`), то есть от размера экрана приложения, а не окна:
   - по ширине: до 359 px — меньше заголовки и кнопки «Далее» (128 px), меньше подписи меню; до 379 px — у ошибки поля прячется иконка; до 399 px — убираются принудительные переносы в вопросах; от 414 px — крупнее заголовки;
   - по высоте: до 640 px — компактнее шапка и отступы; до 560 px — при открытой клавиатуре в чате прячется дисклеймер; до 460 px (горизонтально) — иллюстрации 150 px, перебивки сжимаются; до 420 px — компактное меню и лист отзыва; до 200 px — минимальная шапка чата.
2. **Безопасные зоны** берутся из устройства: `--sat` и `--sab` = `env(safe-area-inset-top/bottom)` (см. `:root` в `app.css`), боковые — `env(safe-area-inset-left/right)` у `.mn`, `.nv`, `.hd`. Значения `--sat: 47px; --sab: 34px` и рамка `#frame` в эталонах — только имитация iPhone для снимка, **в продукт не переносить**. В `<meta name="viewport">` нужны `viewport-fit=cover` и `interactive-widget=resizes-content`.
3. **Часть адаптива — в коде `prototype/src/app.js`, её обязательно перенести:**
   - `viewport()` — режим клавиатуры: класс `.kb` у `#app` ставится, когда видимая область стала ниже (`visualViewport`), **а не по фокусу в поле** — иначе на Android, где клавиатуру закрывают кнопкой «Назад», меню и кнопка пропадают при закрытой клавиатуре. В режиме `.kb` меню прячется, «Готово» в профиле уходит в конец формы;
   - `fitName()` — длинная кличка на главной уменьшается до 30 px, чтобы поместиться в строку;
   - `fitErr()` — длинная ошибка у поля переносится, занимает не больше 60 % строки и не наезжает на поле под ней;
   - `sbar()` — ползунок прокрутки двигается вместе с текстом;
   - `reveal()` — прокрутка к полю внутри экрана (не `scrollIntoView`, он двигает всю страницу).
4. **Эталоны на других размерах** лежат рядом с основными: `<id>--320x568.html` (маленький телефон), `<id>--667x375.html` (горизонтально), `<id>--kb.html` (открыта клавиатура). Список — в `handoff/README.md`.

## Десктоп

Отдельного макета для компьютера нет. На широком экране (от 760 px) показывать ту же мобильную версию: колонка шириной 390–430 px по центру, на всю высоту окна, фон страницы вокруг — `#e9e7e1` (`--shell` в `app.css`), меню внизу колонки. Допустим и вариант как в прототипе — телефон в рамке по центру, но без пульта настроек: правила `#panel` в продукт не переносить.

## Как проверить, что перенесено без искажений

1. Каждый экран из `handoff/screens` открыть рядом с вашим на 390 × 844 и сравнить (лучше наложением скриншотов: допустимы только различия сглаживания шрифтов).
2. Пройти сценарий: вход → профиль → анкета (Введение, 7 разделов, выход «×» и продолжение) → план → меню → чат. Ожидаемые шаги — `tests/flow.js` и `docs/handoff.md`.
3. Проверить размеры 320 × 568, 360 × 640, 390 × 844, 430 × 932 и горизонтальное 667 × 375, с открытой клавиатурой и с крупным системным шрифтом: нет наложений, обрезанных и перекрытых кнопок (логика проверки — `tests/matrix.js`). Для ключевых экранов сравнить с эталонами `--320x568`, `--667x375`, `--kb`.
4. Открыть на компьютере: мобильная версия колонкой по центру.

## Готовый промпт для ИИ-ассистента

> Перенеси мобильный интерфейс Хвостуна в этот проект на [ваш стек] строго по `AGENTS.md`, включая разделы «Адаптив» и «Десктоп». Эталоны экранов — `handoff/screens` (карта — `handoff/README.md`), логика — `prototype/src/app.js`, данные и запросы к серверу — `docs/handoff.md`, тексты анкеты — `prototype/src/cbarq-questions.json`. Разметку, классы, тексты и CSS экранов копируй без изменений, стили каждого экрана изолируй, общий адаптив из `prototype/src/app.css` подключи один раз. Иди по разделам карты эталонов; после каждого экрана открой его рядом с эталоном на 390 × 844 и убедись, что они совпадают.
